근거: [적합성 평가 D-02 재판정](../07_%5B%EB%B6%84%EC%84%9D%5D%20%ED%83%9C%EC%8A%A4%ED%81%AC%20%EC%B6%94%EC%B6%9C%20%EB%B0%A9%EB%B2%95%EB%A1%A0%20%EC%A0%81%ED%95%A9%EC%84%B1%20%ED%8F%89%EA%B0%80%20%28%EC%97%B0%EA%B8%88%ED%94%8C%EB%9F%AC%EC%8A%A4%29.md) · PRD v3.1 §5 · §8.6 · §8.7

> **이 Epic은 D-02 재판정으로 추가되었다.** 최초 적합성 평가는 "SRS-002에 시험 요구가 없다"며 이관 처리했으나, **PRD §8.6~8.7에 검증 대상이 명시되어 있었다.** 원래 판정이 SRS-002만 근거로 삼은 오류였다.

**이 Epic은 그 위의 층을 다룬다** — 요구사항 추적, 통합 수준 전이, 예외 계열 전건 대응, 사용자 여정.

## FR-051 — GWT 인수 기준 76건 ↔ 시험 케이스 추적 매트릭스

**labels:** `test, part:backend, epic:TST, complexity:H, wave:W5`

### 🎯 Summary
PRD가 정의한 인수 기준 **76건**이 각각 어떤 시험으로 검증되는지 매핑한다. **D-02의 본체**다 — 지금은 기준이 있는데 그것을 무엇으로 확인하는지가 비어 있다.

### 🔗 References
- PRD v3.1 §5 — Given-When-Then 표 12개 · AC 총 76행
- `FR-016` 검증 데이터셋 시험 (시험 기반)

### ✅ Task Breakdown
- [ ] PRD §5의 AC 표 12개에서 76행을 추출해 목록화
- [ ] 각 AC를 **검증 층**으로 분류 — 단위 / 통합 / E2E / 수동
- [ ] AC ↔ 시험 케이스 ID 매핑 표 작성
- [ ] **매핑되지 않는 AC를 식별**하고 사유를 기록 (수동 검증 · 측정 불가 등)
- [ ] 매핑 표를 CI에서 대조 가능한 형식으로 (기계 검증 가능하게)

### 🧪 Acceptance Criteria
**Scenario 1 — 76건 전건에 판정 근거가 생긴다**
- Given: PRD §5의 AC 76건에 대해
- When: 매핑 표를 조회하면
- Then: 각 AC마다 **시험 케이스 ID 또는 "수동 검증" 사유**가 지정되어 있다

**Scenario 2 (실패 흐름) — 미매핑이 드러난다**
- Given: 새 AC가 PRD에 추가되었는데 시험이 없으면
- When: 대조를 실행하면
- Then: **미매핑으로 검출된다.** 조용히 넘어가지 않는다

### ⚙️ Constraints
- ⚠️ **AC 문구를 시험에 맞게 고치지 않는다.** 검증하기 어려우면 그 사실을 기록한다
- 매핑만 하고 시험을 작성하지 않는 태스크다. 실제 시험은 FR-052~054와 각 기능 태스크가 담당
- 밴드 검증값은 [PRD·프로토타입 불일치(OI-15)](../04_SRS_%EC%97%B0%EA%B8%88%ED%94%8C%EB%9F%AC%EC%8A%A4_%EA%B8%B0%EC%88%A0%EC%A0%9C%EC%95%BD%EB%B0%98%EC%98%81_v1.0.md) 미해결이므로 **합격 판정에서 제외**하고 사유를 남긴다

### 🏁 DoD
- [ ] AC 76건 전건 매핑 또는 사유 기록
- [ ] 기계 대조 스크립트 동작
- [ ] 미매핑 건수와 사유 목록 산출

### 🚧 Dependencies & Blockers
- **Depends on:** FR-016
- **Blocks:** None

## FR-052 — 상태 전이 통합 시험 (허용 16종 + 금지 5종)

**labels:** `test, part:backend, epic:TST, complexity:H, wave:W9, critical-path`

### 🎯 Summary
`FR-013`이 **판정 로직**을 시험한다면 이 태스크는 **실제 Action이 전이를 일으켜 DB에 반영되는지**를 시험한다. 되는 것뿐 아니라 **안 되어야 하는 것**을 확인하는 것이 핵심이다.

### 🔗 References
- PRD v3.1 §8.6 상태 전이 매트릭스 — T-01~T-16 + 금지 전이 5종
- SRS-002 §4.4 트랜잭션 경계 · `assertTransition`
- `FR-013` 도메인 판정 · `FR-022` 전송 확정

### ✅ Task Breakdown
- [ ] 허용 전이 **16종(T-01~T-16)** 각각을 Action 호출로 재현하는 시험
- [ ] **금지 전이 5종**을 시도해 거부되는지 확인하는 시험
- [ ] 전이 후 `Transfer` · `TradingWindow` · `AuditLog` 상태를 함께 검증
- [ ] 동시 전이 시험 — 같은 건에 두 요청이 동시에 오면 하나만 반영 (`TEC-TX-003`)
- [ ] 트랜잭션 롤백 시험 — 감사 로그 실패 시 상태도 되돌아가는지 (`TEC-TX-001`)

### 🧪 Acceptance Criteria
**Scenario 1 — 허용 전이 16종이 전부 통과한다**
- Given: 각 전이의 시작 상태를 만든 뒤
- When: 해당 Action을 호출하면
- Then: 목표 상태로 전이되고 `AuditLog`가 함께 적재된다

**Scenario 2 (실패 흐름) — 금지 전이 5종이 전부 거부된다**
- Given: 금지 전이의 시작 상태에서
- When: 그 전이를 시도하면
- Then: **거부되고 상태가 변하지 않는다.** 특히 `COMPLETED` → 진행 중 되돌리기는 회복 불가 사고다

**Scenario 3 — 동시 전이가 한 번만 반영된다**
- Given: 동일 건에 전이 요청 2건이 동시에 도착하면
- When: 둘 다 처리되면
- Then: 하나만 상태를 바꾸고 다른 하나는 거부 또는 최초 결과를 반환한다

**Scenario 4 (실패 흐름) — 로그 실패 시 전이가 롤백된다**
- Given: 감사 로그 적재를 실패시킨 상태에서
- When: 전송을 확정하면
- Then: **상태 변경도 롤백된다** (`SRS-FR-029`)

### ⚙️ Constraints
- **21건 전건 시험이 요구사항이다.** 허용만 시험하면 절반만 검증한 것
- `FR-013`과 **층이 다르다** — 여기는 통합(Action → DB), FR-013은 단위(순수 함수)
- ⚠️ `FR-022`가 OPEN-TEC-007에 걸려 있어 **전송 관련 전이는 그 해제 후** 완결된다

### 🏁 DoD
- [ ] 허용 16 + 금지 5 = **21건 전건 시험 통과**
- [ ] 동시 전이 시험 통과
- [ ] 롤백 시험 통과
- [ ] PRD §8.6 매트릭스와 1:1 대조 완료

### 🚧 Dependencies & Blockers
- **Depends on:** FR-013 · FR-022
- **Blocks:** None
- ⚠️ **임계 경로.** 이 태스크가 경로 종점이며, 이 때문에 하한이 39일 → 45일이 되었다.

## FR-053 — 예외·멱등·정합성 시험 (E-01~12 · ID-1~5 · RC-1~5)

**labels:** `test, part:backend, epic:TST, complexity:H, wave:W7`

### 🎯 Summary
PRD §8.7이 정의한 예외 **12건**, 멱등 규칙 **5건**, 정합성 규칙 **5건**이 전건 대응되는지 확인한다. **금융에서 사고가 실제로 나는 자리다.**

### 🔗 References
- PRD v3.1 §8.7 — 예외 `E-01`~`E-12` · 멱등 `ID-1`~`ID-5` · 정합성 `RC-1`~`RC-5`
- SRS-002 §5.3 `TEC-DB-014` 멱등 유니크 · §4.3 `TEC-ACT-002`

### ✅ Task Breakdown
- [ ] 예외 **E-01~E-12** 각각을 유발해 정의된 동작이 나오는지 시험
- [ ] 멱등 **ID-1~ID-5** — 중복 요청·중복 전문·중복 배치 각각
- [ ] 정합성 **RC-1~RC-5** — 3자 불일치를 인위적으로 만들고 검출·보정 확인
- [ ] 순서 뒤바뀜 수신 시험 (`messageSeq` 역순)
- [ ] 전문 누락 시험 — 중간 단계가 오지 않을 때의 동작

### 🧪 Acceptance Criteria
**Scenario 1 — 예외 12건이 정의된 대로 처리된다**
- Given: 각 예외 조건을 유발하면
- When: 시스템이 처리하면
- Then: PRD §8.7에 정의된 동작과 **일치한다**

**Scenario 2 — 중복이 두 번 반영되지 않는다**
- Given: 동일 `requestId` 요청 또는 동일 전문을 두 번 보내면
- When: 처리되면
- Then: **한 번만 반영되고 최초 결과가 반환된다**

**Scenario 3 (실패 흐름) — 순서 뒤바뀜이 상태를 오염시키지 않는다**
- Given: 단계 전문이 역순으로 도착하면
- When: 처리되면
- Then: 뒤늦은 이전 단계 전문이 **현재 상태를 뒤로 돌리지 않는다**

**Scenario 4 — 정합성 불일치가 검출된다**
- Given: 원장과 자체 상태를 인위적으로 어긋나게 만들면
- When: 정합성 배치가 실행되면
- Then: 불일치가 유형별로 검출되고, 자동 보정 불가 건은 **덮어쓰지 않고** 기록된다

### ⚙️ Constraints
- **22건(12+5+5) 전건 대응이 요구사항이다**
- ⚠️ `FR-028`(전문 수신)이 OPEN-TEC-004에 걸려 있어 전문 관련 예외는 그 해제 후 완결
- 정합성 시험은 데이터를 인위적으로 어긋나게 만들어야 한다 — **운영 DB에서 수행하지 않는다**

### 🏁 DoD
- [ ] E-01~E-12 전건 시험 통과
- [ ] ID-1~ID-5 전건 시험 통과
- [ ] RC-1~RC-5 전건 시험 통과
- [ ] PRD §8.7과 1:1 대조 완료

### 🚧 Dependencies & Blockers
- **Depends on:** FR-020 · FR-028 · FR-032
- **Blocks:** None

## FR-054 — E2E 고객 여정 시험

**labels:** `test, part:frontend, epic:TST, complexity:M, wave:W9`

### 🎯 Summary
개별 기능이 아니라 **여정 전체**가 이어지는지 확인한다. 부품이 다 멀쩡한데 조립이 틀린 경우를 잡는다.

### 🔗 References
- PRD v3.1 §5 사용자 스토리
- SRS-002 §3.1 화면 12종

### ✅ Task Breakdown
- [ ] **여정 1** — 사전 조회 → 예약 → 전송 → 현황 확인 → 완료 (기능1 정상 경로)
- [ ] **여정 2** — 인출 시뮬레이션 → 금액 조정 → 결과 확인 → 비과세 비교 (기능2)
- [ ] **여정 3 (예외)** — 거절·중단 상태에서 현황판 진입 및 안내 확인
- [ ] **여정 4 (폴백)** — 폴백 ③단계에서 대략치 병기가 표시되는지
- [ ] 화면 간 **값 일치 검증** — 현황판 밴드 = 근거 화면 밴드

### 🧪 Acceptance Criteria
**Scenario 1 — 기능1 정상 여정이 끝까지 이어진다**
- Given: 이관 가능한 계좌로
- When: 사전 조회부터 완료까지 진행하면
- Then: 각 단계 화면이 순서대로 열리고 상태가 일관되게 표시된다

**Scenario 2 — 두 화면의 밴드 값이 같다**
- Given: 현황판에 밴드가 표시된 상태에서
- When: 완료일 근거 화면으로 이동하면
- Then: **같은 밴드 값**이 표시된다 (당일 캐시 동일 출처)

**Scenario 3 (실패 흐름) — 예외 상태에서도 여정이 막히지 않는다**
- Given: 거절된 건에 대해
- When: 현황판에 진입하면
- Then: 거절 사유가 매핑 문구로 표시되고 다음 행동이 안내된다

### ⚙️ Constraints
- E2E는 느리고 자주 깨진다. **소수로 유지한다** — 여정 4개를 넘기지 않는다
- ⚠️ 기능1 여정은 폴백 ③단계 기준으로만 검증 가능 (OPEN-TEC-004)
- 기능2 여정은 개발 가능하나 **출시는 LEGAL-Q1** 판정 후

### 🏁 DoD
- [ ] 여정 4종 시험 통과
- [ ] 화면 간 값 일치 검증 통과
- [ ] 실행 시간 기록 (느려지면 축소 판단 근거)

### 🚧 Dependencies & Blockers
- **Depends on:** FR-040 · FR-041 · FR-042
- **Blocks:** None

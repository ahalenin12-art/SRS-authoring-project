## FR-034 — shadcn/ui 컴포넌트 14종 도입 및 매핑

**labels:** `feature, part:frontend, epic:UIF, complexity:M, wave:W3`

### 🎯 Summary
§6.1 매핑표대로 shadcn/ui 컴포넌트를 도입한다. 화면 5건과 FR-035의 선행이다.

### 🔗 References
- SRS-002 §6.1 컴포넌트 매핑 (14종) · C-TEC-004
- SRS-002 §6.3 `TEC-UI-012` — 기본 ARIA 속성을 제거하지 않는다

### ✅ Task Breakdown
- [ ] 매핑 14종 도입 — `Card` `Progress` `Table` `Accordion`+`Badge` `Sheet` `Collapsible` `Input`+`Slider` `Select` `Alert` `AlertDialog` `ScrollArea`
- [ ] UX-002의 시각 스타일 적용
- [ ] 커스터마이즈 시 ARIA 속성 보존 검증 (`TEC-UI-012`)
- [ ] Tailwind 토큰을 UX-001 디자인 토큰과 1:1 대응

### 🧪 Acceptance Criteria
**Scenario 1 — 매핑 14종이 렌더된다**
- Given: 도입된 컴포넌트로
- When: 샘플 페이지를 렌더하면
- Then: 14종이 디자인 시안대로 표시된다

**Scenario 2 (실패 흐름) — ARIA 제거가 검출된다**
- Given: 커스터마이즈 과정에서 ARIA 속성이 제거되면
- When: 접근성 검사를 실행하면
- Then: **검출되어 실패한다** (`TEC-UI-012`)

### ⚙️ Constraints
- `TEC-UI-012` — shadcn/ui 기본 접근성 속성을 제거하지 않는다
- 색·간격을 임의값으로 쓰지 않는다. **Tailwind 토큰에서만** (C-TEC-004의 목적)

### 🏁 DoD
- [ ] 14종 도입 및 렌더 확인
- [ ] ARIA 보존 검사 통과
- [ ] 토큰 외 임의값 사용 0건

### 🚧 Dependencies & Blockers
- **Depends on:** FR-001 · UX-002
- **Blocks:** FR-035 · FR-039 · FR-043 · FR-048 · FR-049

## FR-035 — 공통 표기 컴포넌트 6종 구현

**labels:** `feature, part:frontend, epic:UIF, complexity:M, wave:W4`

### 🎯 Summary
표기 규칙을 **컴포넌트 타입으로 강제**한다. 화면이 12개라 한 곳에서만 실수해도 규칙이 깨지므로, 화면별 구현에 맡기지 않는다.

### 🔗 References
- SRS-002 §6.2 공통 표기 컴포넌트 (필수) · `TEC-UI-001` ~ `TEC-UI-003`
- SRS-002 §6.2 `BandDisplayProps` 타입 예시

### ✅ Task Breakdown
- [ ] `<BandDisplay>` — `endBandFrom`·`endBandTo`·`businessDaysMin`·`businessDaysMax`·`approximate?`. **단일 날짜 prop을 타입에 정의하지 않는다** (`SRS-FR-018`·`036`)
- [ ] `<LayerBadge>` — `layer`에 따라 확정(분단위 시각) / 추정(비단정 서술) 분기 (`SRS-FR-034`·`035`)
- [ ] `<SimulationLabel>` — 모의계산 라벨 sticky 고정 (`SRS-FR-082`)
- [ ] `<StatusLabel>` — enum → 한글 표시명 변환. **원본 enum을 렌더하지 않는다** (`SRS-FR-047`)
- [ ] `<MoneyText>` — 원 단위 확정 금액. **비율 단독 표기 차단** (`SRS-FR-093`)
- [ ] `<MaskedAccount>` — 계좌번호 중간 4자리 마스킹 (`SRS-SEC-009`)

### 🧪 Acceptance Criteria
**Scenario 1 (컴파일 방어) — 단일 날짜를 넣을 수 없다**
- Given: `<BandDisplay endDate={...} />` 같이 단일 날짜를 전달하면
- When: 타입 체크를 실행하면
- Then: **컴파일 오류가 발생한다.** 코드 리뷰까지 갈 필요가 없다

**Scenario 2 — 확정/추정이 다르게 표시된다**
- Given: `layer`가 `CONFIRMED` / `ESTIMATED`일 때
- When: `<LayerBadge>`를 렌더하면
- Then: 전자는 분단위 시각, 후자는 비단정 서술로 표시된다

**Scenario 3 — 계좌번호가 마스킹된다**
- Given: 계좌번호를 전달하면
- When: `<MaskedAccount>`를 렌더하면
- Then: 중간 4자리가 마스킹되어 표시된다

**Scenario 4 — 내부 enum이 노출되지 않는다**
- Given: `TransferStatus` enum 값을 전달하면
- When: `<StatusLabel>`을 렌더하면
- Then: 한글 표시명이 나오고 **원본 enum 문자열이 DOM에 나타나지 않는다**

### ⚙️ Constraints
- `TEC-UI-001` — 완료일·해제일은 반드시 `<BandDisplay>`. 날짜 직접 렌더 금지
- `TEC-UI-002` — 상태 표시는 반드시 `<StatusLabel>`
- `TEC-UI-003` — 금액 표시는 반드시 `<MoneyText>`
- ⚠️ **타입 설계가 곧 규칙 강제 수단이다.** 편의를 위해 단일 날짜 prop을 추가하면 이 태스크의 의미가 사라진다

### 🏁 DoD
- [ ] 컴포넌트 6종 구현
- [ ] 단일 날짜 prop 부재를 컴파일 시험으로 확인
- [ ] 시나리오 4건 전부 통과

### 🚧 Dependencies & Blockers
- **Depends on:** FR-003 · FR-034 · UX-003
- **Blocks:** FR-036 · FR-038 · FR-040 · FR-041 · FR-046

## FR-036 — 표기 규칙 위반 차단 ESLint 커스텀 룰

**labels:** `chore, part:frontend, epic:UIF, complexity:M, wave:W5`

### 🎯 Summary
`TEC-UI-001~003`을 도구로 강제한다. 컴포넌트를 만들어도 **쓰지 않으면 소용없기 때문**이다.

### 🔗 References
- SRS-002 §6.2 `TEC-UI-004` — ESLint 커스텀 룰 또는 코드 리뷰 체크리스트로 차단 (`SRS-NFR-MNT-004`)

### ✅ Task Breakdown
- [ ] 날짜 직접 렌더 검출 룰 — `<BandDisplay>` 밖에서 완료일·해제일 렌더 금지
- [ ] enum 직접 렌더 검출 룰 — `<StatusLabel>` 우회 금지
- [ ] 금액 직접 렌더 검출 룰 — `<MoneyText>` 우회 금지
- [ ] 룰을 빌드 파이프라인에 편입
- [ ] 예외 허용 목록과 그 사유 문서화

### 🧪 Acceptance Criteria
**Scenario 1 (실패 흐름) — 우회 코드가 빌드를 막는다**
- Given: 완료일을 `<BandDisplay>` 없이 직접 렌더하는 코드를 작성하면
- When: 린트를 실행하면
- Then: **오류가 발생하고 빌드가 실패한다**

**Scenario 2 — 정상 사용은 통과한다**
- Given: 표기 컴포넌트를 규약대로 사용하면
- When: 린트를 실행하면
- Then: 통과한다

### ⚙️ Constraints
- ⚠️ 코드 리뷰 체크리스트로 대체 가능하지만, **사람의 주의력에 의존하는 방식은 6개월 뒤 깨진다.** 룰 구현을 권고
- 오탐이 많으면 팀이 룰을 끄게 된다. 정밀도를 우선한다

### 🏁 DoD
- [ ] 룰 3종 구현
- [ ] 우회 코드 차단 시험 통과
- [ ] 오탐 0건 확인 (기존 코드베이스 전체 스캔)

### 🚧 Dependencies & Blockers
- **Depends on:** FR-035
- **Blocks:** None

## FR-037 — 접근성 구현 (대비 토큰 · `break-keep` · ARIA 보존)

**labels:** `feature, part:frontend, epic:UIF, complexity:M, wave:W2`

### 🎯 Summary
§6.3의 접근성 요구 3종을 구현한다. 디자인 토큰(UX-001)이 확정되면 바로 착수할 수 있어 **W2에 일찍 배치**했다.

### 🔗 References
- SRS-002 §6.3 `TEC-UI-010` · `TEC-UI-011` · `TEC-UI-012`

### ✅ Task Breakdown
- [ ] Tailwind 색상 토큰을 **대비 검증 통과 팔레트로 고정** (본문 4.5:1 · 큰 텍스트 3:1)
- [ ] `break-keep` 유틸리티를 전역 기본값으로 (한글 어절 단위 줄바꿈)
- [ ] 대비 자동 검사를 빌드 또는 시험 단계에 편입
- [ ] 키보드 포커스 가시성 확인

### 🧪 Acceptance Criteria
**Scenario 1 — 대비가 기준을 만족한다**
- Given: 확정된 색상 토큰으로
- When: 대비 검사를 실행하면
- Then: 본문 4.5:1 · 큰 텍스트 3:1을 **전건 만족한다**

**Scenario 2 — 한글이 어절 단위로 끊긴다**
- Given: 긴 한글 문장을 좁은 폭에서 렌더하면
- When: 줄바꿈이 발생하면
- Then: 단어 중간이 아니라 **어절 경계**에서 끊긴다

### ⚙️ Constraints
- `TEC-UI-010` — 대비 검증 통과 팔레트로 **고정**한다. 화면별 임의 색상 금지
- `TEC-UI-011` — `break-keep`을 전역 기본값으로

### 🏁 DoD
- [ ] 대비 검사 전건 통과
- [ ] `break-keep` 전역 적용 확인
- [ ] 포커스 가시성 확인

### 🚧 Dependencies & Blockers
- **Depends on:** FR-001 · UX-001
- **Blocks:** None

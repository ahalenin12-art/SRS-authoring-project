### 🎯 Summary
`FR-013`이 **판정 로직**을 시험한다면 이 태스크는 **실제 Action이 전이를 일으켜 DB에 반영되는지**를 시험한다. 되는 것뿐 아니라 **안 되어야 하는 것**을 확인하는 것이 핵심이다.

### ✅ Task Breakdown
- [ ] 허용 전이 **16종(T-01~T-16)** 각각을 Action 호출로 재현하는 시험
- [ ] **금지 전이 5종**을 시도해 거부되는지 확인하는 시험
- [ ] 전이 후 `Transfer` · `TradingWindow` · `AuditLog` 상태를 함께 검증
- [ ] 동시 전이 시험 — 같은 건에 두 요청이 동시에 오면 하나만 반영 (`TEC-TX-003`)
- [ ] 트랜잭션 롤백 시험 — 감사 로그 실패 시 상태도 되돌아가는지 (`TEC-TX-001`)

### 🧪 Acceptance Criteria
**Scenario 1 — 허용 전이 16종이 전부 통과한다**
- Given: 각 전이의 시작 상태를 만든 뒤
- When: 해당 Action을 호출하면
- Then: 목표 상태로 전이되고 `AuditLog`가 함께 적재된다

**Scenario 2 (실패 흐름) — 금지 전이 5종이 전부 거부된다**
- Given: 금지 전이의 시작 상태에서
- When: 그 전이를 시도하면
- Then: **거부되고 상태가 변하지 않는다.** 특히 `COMPLETED` → 진행 중 되돌리기는 회복 불가 사고다

**Scenario 3 — 동시 전이가 한 번만 반영된다**
- Given: 동일 건에 전이 요청 2건이 동시에 도착하면
- When: 둘 다 처리되면
- Then: 하나만 상태를 바꾸고 다른 하나는 거부 또는 최초 결과를 반환한다

**Scenario 4 (실패 흐름) — 로그 실패 시 전이가 롤백된다**
- Given: 감사 로그 적재를 실패시킨 상태에서
- When: 전송을 확정하면
- Then: **상태 변경도 롤백된다** (`SRS-FR-029`)

### ⚙️ Constraints
- **21건 전건 시험이 요구사항이다.** 허용만 시험하면 절반만 검증한 것
- `FR-013`과 **층이 다르다** — 여기는 통합(Action → DB), FR-013은 단위(순수 함수)
- ⚠️ `FR-022`가 OPEN-TEC-007에 걸려 있어 **전송 관련 전이는 그 해제 후** 완결된다

### 🎯 Summary
성능 목표 5종을 실제로 측정하고, **콜드 스타트가 매매창 판정에 미치는 영향**을 수치로 확보한다. 이 결과가 OPEN-TEC-003의 답이자 **G2 게이트**다.

### 🔗 References
- SRS-002 §9.1 CONFLICT-01 — "완화 후에도 p95 500ms 보장이 확정되지 않는다. **Phase 0에서 실측 후 판정**"
- SRS-002 §11 OPEN-TEC-003 — 매매창 판정 응답 시간 실측
- 선행 SRS `SRS-NFR-PERF-001` ~ `005`

### ✅ Task Breakdown
- [ ] 부하 시험 시나리오 작성 (동시 요청률·지속 시간 정의)
- [ ] **측정 대상 5종** 계측
- [ ] **콜드 스타트 포함 / 제외** 두 조건으로 각각 측정
- [ ] 운영 동급 환경에서 지속 측정 (순간 측정 금지)
- [ ] 측정 조건 4종(부하·환경·기간·콜드스타트 포함 여부)을 결과에 명시
- [ ] `SRS-NFR-REL-004` 가드레일 지표 영향 추정 — 판정 지연으로 인한 정상 주문 거부율

### 📊 측정 대상

| 대상 | 목표 | 위험도 | 미달 시 |
| --- | --- | :---: | --- |
| **매매창 판정 API** | p95 ≤ 500ms | **최고** | 정상 주문이 `LOCKED`로 거부됨. 가드레일 소진 |
| 홈 진행 카드 | p95 ≤ 0.8초 | 중 | 체감 지연 |

| 인출액 변경 재계산 | p95 ≤ 300ms | 하 | §9.3에서 클라이언트 실행으로 완화됨 |

### 🧪 Acceptance Criteria
**Scenario 1 — 측정 조건이 특정된 결과가 나온다**
- Given: 부하 시험을 실행하면
- When: 결과를 받으면
- Then: **부하·환경·기간·콜드스타트 포함 여부 4조건이 명시된** p95 수치 5종이 확보된다

**Scenario 2 — 콜드 스타트 영향이 분리된다**
- Given: 매매창 판정에 대해
- When: 콜드 스타트 포함/제외로 각각 측정하면
- Then: **두 수치의 차이**가 콜드 스타트 영향으로 정량화된다

**Scenario 3 (판정) — 목표 미달 시 판정이 기록된다**
- Given: p95가 목표를 초과하면
- When: 결과를 판정하면
- Then: **OPEN-TEC-003이 미해결로 유지되고 출시 판정이 보류된다.** 수치를 완화하지 않는다

### ⚙️ Constraints
- ⚠️ **네 조건 없는 수치는 OPEN-TEC-003의 답이 되지 못한다.** "p95 480ms입니다"만으로는 판정할 수 없다
- ⚠️ **합격 기준과 알람 임계는 다르다.** 합격은 p95 ≤ 0.8초, 운영 알람은 p95 > 1.0초 10분 지속 — 같게 두면 목표를 아슬아슬하게 지키는 동안 계속 울린다
- 목표 미달 시 **수치를 조정하지 않는다.** 아키텍처를 바꾸거나 PRD 변경으로 올린다

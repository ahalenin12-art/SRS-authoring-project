## 1. Introduction

### 1.1 Purpose

이 문서는 연금플러스의 소프트웨어 요구사항을 ISO/IEC/IEEE 29148:2018에 따라 정의한다.

**해결 대상 문제** — KB증권의 일반 고객(PB 미배정)은 연금 이전을 결심한 시점에 상품별 이전 가능 여부, 실시간 진행 현황, 추가 운용지시 제한 사유를 확인할 수단이 없다. 이로 인해 투자손실을 최소화하며 이관을 완료하지 못한다. [REF-01 §1.4]

이관 처리 속도는 예탁결제원 단일 인프라에 종속되어 어느 증권사도 단축할 수 없다. 따라서 이 시스템은 처리 속도를 개선 대상으로 삼지 않는다. **처리 상태의 가시화**와 **인출 시 세액의 사전 산출**이 목적이다.

대상 독자는 개발팀, QA, 법무·컴플라이언스, 연금시스템 운영팀이다.

**보존 정책 근거**

| 구분 | 기간 | 근거 |
| --- | :---: | --- |
| 이관 거래 기록 · 감사 로그 | **정책 확정값 · 설계 상한 10년** | 법무·정보보호 정책으로 확정 (OI-17). 상법 §64 상사채권 소멸시효는 **5년**이므로 10년의 직접 근거가 아니다 |
| 계좌 원장 파생 데이터 | 계좌 해지 + 5년 | 전자금융거래법 기록 보존 |
| 시뮬레이션 결과 | 90일 | **실제 거래가 아니므로 장기 보존 불필요.** 최소 수집 원칙 |
| 밴드 산출 중간값 (`confidence`) | 90일 | 지표 집계 후 가치 소멸 |
| 세율 시행일 이력 | 영구 | 과거 계산의 근거를 복원할 수 있어야 함 |

> **시뮬레이션 결과를 90일로 짧게 잡은 이유.** `WITHDRAWAL_REQUEST`는 실제 출금이 아니라 계산 기록이다(CON-15). 개인의 인출 계획은 민감 정보이므로 최소 수집·최소 보존 원칙을 적용한다. 다만 지표 집계에 필요한 **익명 집계값**은 별도 보관한다.

#### 6.3.1 상태 전이 매트릭스

| BD-7 | 밴드 폭 | 영업일 수로 계산. 달력일 아님 |
| BD-8 | 최소 폭 | 2영업일. 미달 시 종료일을 밀어 확보 |

## 1. 요약

**판정: 조건부 적합.** Step 1·2는 충족, Step 3·4에서 결함 3건을 발견했고 그중 **1건만 태스크 추가로 보정하고 2건은 보정하지 않는다.**

| Step | 대상 | 판정 | 근거 |
| --- | --- | :---: | --- |
| **Step 1** 계약·규약·데이터 명세 | SRS §3·§4·§5·§6·§8 | **충족** | 구조적 산출물 6종이 태스크와 1:1 대응 |
| **Step 2** 로직·상태 변경 분리 | SRS §4.2·§5.4 | **충족** | 읽기/쓰기 Action 분리 · 도메인 순수 모듈 격리 |
| **Step 3** AC → 테스트 태스크 | PRD §5 GWT 76건 | **조건부** | SRS 준거로는 충족, 방법론 준거로는 미흡 |
| **Step 4** NFR·의존성 매핑 | SRS §9·§11 | **부분 미흡** | 의존성 충족 · **성능 실측 태스크 누락** |

**보정 결론.** 성능 실측 태스크 1건만 추가한다(§3.2). 나머지 2건은 SRS-002에 근거가 없어 추가하지 않고 **소관 문서로 이관**한다. 근거 없는 태스크를 만드는 것은 "SRS에 명시되지 않은 기능을 추가하지 않는다"는 추출 원칙 위반이다.

## 2. Step별 상세 평가

### 2.1 Step 1 — 계약·규약 및 데이터 명세 — 충족

SRS-002가 확정한 구조적 산출물이 빠짐없이 태스크로 변환되었는지 대조했다.

| SRS 산출물 | 문서 근거 | 건수 | 대응 태스크 (v2) | 대응 |
| --- | --- | ---: | --- | :---: |
| App Router 경로 | §3.1·3.2·3.3 | 19 | FR-027~029(연동 3) · FR-031~033(배치 4) · FR-038~049(화면 12) | 충족 |
| Server Action | §4.2 | 7 | FR-021 · FR-022 · FR-023 · FR-024(2) · FR-025(2) | 충족 |
| Prisma enum | §5.2 | 7 | FR-003 | 충족 |
| Prisma 모델 | §5.2 | 16 | FR-005 | 충족 |
| 스키마 레벨 제약 | §5.3 TEC-DB-010~015 | 6 | FR-006(3) · FR-007(RLS) | 충족 |
| shadcn/ui 매핑 | §6.1 | 14 | FR-034 | 충족 |
| 공통 표기 컴포넌트 | §6.2 | 6 | FR-035 | 충족 |
| 환경 변수 | §8.2 | 12 | FR-002 | 충족 |

**판정 근거.** SRS-002 §13.4의 요약 수치(경로 19 · Action 7 · Route Handler 7 · 모델 16 · 매핑 14 · 표기 컴포넌트 6)와 태스크 대응표가 전건 일치한다. 누락된 산출물이 없다.

> **AI 통합(§7)이 태스크로 나오지 않은 것은 결함이 아니다.** §7.1이 "PRD v3.1에는 AI를 호출하는 기능 요구사항이 존재하지 않는다", "현재 적용 대상 없음"으로 판정했다. `TEC-AI-001~005`는 AI 기능이 **추가될 경우**의 상시 제약이다. 태스크로 만들면 문서에 없는 기능을 만드는 것이 된다.

### 2.2 Step 2 — 로직 및 상태 변경 분리 — 충족

상태를 바꾸는 것과 읽기만 하는 것이 태스크 단계에서 구분되었는지 본다. 구분되지 않으면 **트랜잭션·멱등성·권한 요구가 읽기 기능에까지 번져** 불필요한 복잡도가 생긴다.

| 구분 | 태스크 | SRS 근거 |
| --- | --- | --- |
| **쓰기 (상태 변경)** | FR-021 saveDraft · FR-022 submitTransfer · FR-024 updateDraft/cancelTransfer | §4.2 "상태 변경 Y" |
| **읽기 전용** | FR-023 simulateWithdrawal · FR-025 getPensionLimit/compareWithCertificate | §4.2 "상태 변경 N" · `TEC-ACT-005` "어떤 쓰기도 수행하지 않아야 한다" |
| **순수 계산 (I/O 없음)** | FR-008~FR-015 도메인 모듈 8종 | §5.4 `TEC-DOM-001` "Prisma Client를 import하지 않아야 한다" |
| **횡단 규약** | FR-019 공통 기반 · FR-020 멱등 처리 | §4.3 `TEC-ACT-001·002·004` |

**판정 근거.** 세 계층이 태스크 단위에서 분리되어 있고, 멱등 처리(FR-020)가 쓰기 Action 전체의 선행으로 배치되어 있다. 읽기 전용 Action(FR-023·FR-025)은 FR-020에 의존하지 않는다 — 의존 그래프상으로도 분리가 유지된다.

### 2.3 Step 3 — AC를 테스트 Task로 변환 — 조건부 충족

**여기가 이 추출의 가장 약한 지점이다.**

| 검증 대상 | 건수 | 대응 태스크 | 상태 |
| --- | ---: | --- | :---: |
| 검증 데이터셋 (한도·세액 원 단위 일치) | 6 | FR-016 | 충족 |
| 배포 전 회귀 게이트 | 1 | FR-016 (통합) | 충족 |
| PRD GWT 인수 기준 | 76 | **없음** | 미대응 |
| 상태 전이 (허용 16 + 금지 5) | 21 | **없음** | 미대응 |
| 예외 처리 (E-01~E-12) | 12 | **없음** | 미대응 |

**그러나 이것이 곧 결함은 아니다.** SRS-002가 명시적으로 요구한 시험은 두 건뿐이다.

- `TEC-DOM-004` — "검증 데이터셋 6건이 도메인 모듈 단위 시험으로 자동 검증되어야 한다"
- `TEC-OPS-003` — "프로덕션 배포 전 Preview 배포에서 검증 데이터셋 6건 회귀 시험이 통과해야 한다"

둘 다 FR-016이 덮는다. **SRS-002 준거로는 충족이다.**

GWT 76건·상태 전이 21건·예외 12건에 대한 시험은 **PRD와 선행 SRS(`02_SRS_연금플러스_v1.0.md`)의 소관**이며, SRS-002는 "요구사항을 발명하지 않는다"는 자기 원칙(§12.1) 아래 이를 다루지 않았다. 태스크 추출이 SRS-002를 근거로 삼는 한, 여기서 시험 태스크를 만들어 내면 **근거 없는 태스크**가 된다.

> **판정을 "충족"이 아니라 "조건부"로 두는 이유.** SRS 준거로는 문제가 없지만, 실제 개발에 들어가면 **AC 76건을 무엇으로 검증할지 정해지지 않은 상태**가 된다. 이 공백은 태스크 추출의 결함이 아니라 **상위 문서 간 공백**이다. §3.3에서 이관 처리한다.

### 2.4 Step 4 — NFR 및 의존성 매핑 — 부분 미흡

**의존성 — 충족.** 66건 전부 선행 태스크가 명시되어 있고, 기계 검증으로 순환 참조 0건을 확인했다(§4).

| 지표 | 값 |
| --- | ---: |
| 선행 태스크 명시된 태스크 | 66 / 66 |
| 순환 참조 | 0 |
| 선행 없음 (즉시 착수) | 3 (FR-001 · FR-002 · UX-001) |
| 위상 정렬 깊이 | 8단계 |

**NFR — 항목별로 갈린다.**

| NFR 계열 | SRS 근거 | 대응 태스크 | 판정 |
| --- | --- | --- | :---: |
| 접근성 (대비·줄바꿈·ARIA) | §6.3 `TEC-UI-010~012` | FR-037 · UX-001 | 충족 |
| 보안 (소유권·마스킹·WORM) | §5.3 `TEC-DB-013·015` · §4.3 `TEC-ACT-004` | FR-006 · FR-007 · FR-019 · FR-035 | 충족 |
| 신뢰성 (멱등·트랜잭션) | §4.3·§4.4 · §5.3 `TEC-DB-014` | FR-006 · FR-020 · FR-022 | 충족 |
| 가용성 (커넥션 한도) | §9.4 `TEC-DB-002` | FR-003 | 충족 |
| **성능 (p95 5종 실측)** | §9.1 · `OPEN-TEC-003` | **없음** | **누락** |

**성능만 누락이다. 그리고 이건 SRS 근거가 있는 누락이라 결함이다.**

§9.1은 완화책 3종(Edge Runtime · TTL 캐시 · 워밍)을 제시한 뒤 **"완화 후에도 p95 500ms 보장이 확정되지 않는다. Phase 0에서 실측 후 판정"** 이라고 명시했다. `OPEN-TEC-003`도 실측을 요구한다.

그런데 태스크에는 **완화책 구현(FR-004)만 있고 실측이 없다.** 완화했는지 판정할 수단이 없는 상태로 출시 게이트에 도달한다.

# v2 고유 태스크 ID 수

grep -o '^| UX-[0-9]\{3\}' 'docs/06_[태스크 리스트] 연금플러스_병합판.md' | sort -u | wc -l # → 17

| 검증 항목 | 결과 |

| H 태스크가 병합되지 않았는가 | 통과 (30건 단일 원본 유지) |

## 5. 축약 필요성에 대한 예비 판단

이 평가에서 확인된 사실 중 축약 판단에 영향을 주는 것.

| 사실 | 축약에 대한 함의 |
| --- | --- |
| v1 102건 중 L 복잡도가 20건 | 단독 태스크로 두기에 작은 항목이 다수 |
| 같은 디렉터리·같은 SRS 절의 산출물이 흩어져 있음 | 파일 단위 병합 여지 있음 |

# 7. D-02 재판정 (v1.1)

## 7.1 최초 판정이 틀렸다

§3.3에서 D-02(AC 76건 ↔ 시험 태스크 추적 부재)를 **"SRS 근거 없음"으로 이관** 처리했다. 그 판단이 틀렸다.

| | 최초 판정 (v1.0) | 재판정 (v1.1) |
| --- | --- | --- |
| 근거 확인 범위 | **SRS-002만** | SRS-002 **+ PRD v3.1** |
| 결론 | 근거 없음 → 이관 | **근거 있음 → 태스크 추가** |

**PRD에 검증 대상이 명시되어 있었다.**

| 검증 대상 | 건수 | 출처 |
| --- | ---: | --- |
| GWT 인수 기준 | **76** | PRD §5 (AC 표 12개) |
| 상태 전이 T-01~T-16 | 16 | PRD §8.6 |
| 예외 E-01~E-12 | 12 | PRD §8.7 |
| 멱등 ID-1~ID-5 | 5 | PRD §8.7 |
| 정합성 RC-1~RC-5 | 5 | PRD §8.7 |
| **합계** | **114** | |

**114건의 검증 대상이 있는데 시험 태스크가 `FR-016` 하나뿐이었다.** 이건 이관할 사안이 아니라 보정할 결함이다.

> **왜 놓쳤는가.** 태스크 추출의 근거 문서를 SRS-002로 한정한 것이 원인이다. SRS-002는 "정해진 기술로 어떻게 만드는가"만 다루므로 시험 전략이 없는 것이 당연했다. **근거를 한 문서에서만 찾은 것이 방법론의 결함이었다.**

## 7.4 D-03은 이관을 유지한다 — 사유 갱신

D-03(컴플라이언스 11건 증거 확인)도 PRD §11에 근거가 있다. 그러나 **이관을 유지한다.**

| 판정 | 사유 |
| --- | --- |
| **이관 유지** | 컴플라이언스 증거의 **정의 자체가 법무 판단**이다. 무엇을 증거로 인정할지 정해지지 않은 상태에서 시험 태스크를 만들면 **확인할 대상이 비어 있다** |

**D-02와 D-03의 차이는 근거의 성격이다.** D-02의 검증 대상(전이 16종·예외 12건)은 PRD에 **값으로** 확정되어 있어 바로 시험을 쓸 수 있다. D-03은 **판단이 선행되어야** 한다.

법무 판정 후 이 문서를 v1.2로 갱신하고 태스크를 추가한다.

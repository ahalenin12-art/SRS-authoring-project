# 기술 제약 가드레일

## 언제 쓰는가

- 새 npm 패키지를 추가하려 할 때
- "여기는 Redis를 쓰면 빠른데" 같은 판단이 들 때
- 별도 서버·워커 프로세스를 두고 싶을 때
- 배포·스케줄링·CI 설정을 건드릴 때
- AI 기능을 붙이려 할 때

## 왜 있는가

C-TEC-001~007은 **발주 측이 확정한 제약**이다. 기술적으로 더 나은 대안이 있어도 **제약을 조용히 우회하면 안 된다.** 우회는 발견이 늦고, 발견 시점에는 이미 되돌리기 비싸다.

제약이 요구사항을 깨뜨리는 경우는 **실제로 존재한다.** SRS §9가 그 충돌 7건을 기록한다. 새 충돌을 찾으면 **거기에 적고 논의한다.** 코드로 몰래 해결하지 않는다.

## 확정 제약 — C-TEC-001~007

| ID | 제약 | 상태 |
| --- | --- | :---: |
| **C-TEC-001** | Next.js App Router 기반 **단일 풀스택**. 프론트·백을 분리하지 않는다 | 확정 |
| **C-TEC-002** | 서버 로직은 **Server Actions 또는 Route Handlers**로만. 별도 백엔드 서버 없음 | 확정 |
| **C-TEC-003** | DB는 **Prisma + Supabase(PostgreSQL)** | 확정 |
| **C-TEC-004** | UI는 **Tailwind CSS + shadcn/ui** | 확정 |
| **C-TEC-005** | AI 기능은 **Vercel AI SDK**로 외부 API 호출. 자체 AI 서버 없음 | 조건부 |
| **C-TEC-006** | AI는 **Google Gemini** 기본, 환경 변수만으로 모델 교체 가능 | 조건부 |
| **C-TEC-007** | 배포는 **Vercel 단일화**, Git Push만으로 자동 배포 | 확정 |

## 체크리스트 — 새 의존성·구성요소

**아래에 걸리면 멈추고 사람에게 확인한다.**

| 하려는 것 | 판정 | 근거 | 대신 |
| --- | :---: | --- | --- |
| Express·NestJS·Fastify 서버 추가 | ❌ | C-TEC-002 | Server Actions · Route Handlers |

| Redis·Memcached 등 별도 캐시 서버 | ❌ | C-TEC-003·007 | DB 컬럼 캐시 (`LockWindow.cachedOn`) · 짧은 TTL 인메모리 |
| Prisma 외 ORM·쿼리빌더 추가 | ❌ | C-TEC-003 | Prisma Client |
| Supabase 외 DB 도입 | ❌ | C-TEC-003 | Supabase PostgreSQL |
| Tailwind 외 CSS 프레임워크·CSS-in-JS | ❌ | C-TEC-004 | Tailwind 토큰 · shadcn/ui |
| 자체 추론 서버·로컬 모델 구동 | ❌ | C-TEC-005 | Vercel AI SDK로 외부 호출 |
| 별도 CI/CD 파이프라인 구성 | ❌ | `TEC-OPS-001` | Vercel 자동 배포 |
| 수동 DDL 적용 | ❌ | `TEC-DB-003` | Prisma Migrate |
| 환경별 Prisma 스키마 분기 | ❌ | `TEC-DB-001` | 단일 스키마 |

## 배포·환경 변수 규약

| ID | 규약 |
| --- | --- |
| `TEC-OPS-001` | 배포는 Vercel로 단일화. 별도 CI/CD 파이프라인 금지 |
| `TEC-OPS-002` | Git Push로 배포가 자동 수행되어야 한다 |
| `TEC-OPS-003` | **프로덕션 배포 전 Preview에서 검증 데이터셋 6건 회귀 시험 통과** 필수 |
| `TEC-OPS-004` | 마이그레이션은 빌드 단계에서 `prisma migrate deploy` |
| `TEC-OPS-010` | **비밀 값에 `NEXT_PUBLIC_` 접두사 금지.** 클라이언트 번들 포함 원천 차단 |
| `TEC-OPS-011` | 세율 차단 임계는 환경 변수로. 배포 없이 조정 가능해야 한다 |

**환경 변수 12종**이 §8.2에 확정되어 있다. 새 변수를 추가하면 그 표에 함께 등록한다.

## 배치(Cron) 규약

| ID | 규약 |
| --- | --- |
| `TEC-BATCH-001` | Cron 엔드포인트는 `CRON_SECRET` 검증 없이 실행되지 않아야 한다 |
| `TEC-BATCH-002` | **진입 직후 영업일 검증.** 비영업일이면 처리 없이 반환 |
| `TEC-BATCH-003` | 배치는 **멱등**. 중복 실행 시 동일 결과 보장 |
| `TEC-BATCH-004` | 처리 대상을 페이지 단위로 나눠 실행 시간 한도 내 완료 |
| `TEC-BATCH-005` | 실행 결과(대상·성공·실패·스킵)를 로그로 남긴다 |

> **Vercel Cron은 UTC 기준이고 공휴일을 모른다.** `0 0 * * 1-5`가 KST 09:00 월~금이다. **요일은 Cron이, 공휴일은 핸들러가** 판정한다.

**멱등 처리는 조건을 UPDATE에 포함시켜 원자적으로 한다.** 조회 조건에만 두면 동시 실행에서 깨진다.

```ts
await prisma.lockWindow.updateMany({
  where: { transferId, cachedOn: { lt: today } },   // 조건이 UPDATE 안에
  data:  { endBandFrom, endBandTo, cachedOn: today },
})
```

## AI 기능 — 현재 적용 대상 없음

**SRS §7.1 판정: PRD v3.1에는 AI를 호출하는 기능 요구사항이 존재하지 않는다.**

요구사항 83건을 검토한 결과 계산은 전부 **법정 산식**이고 문구 변환은 **매핑표 기반**이다. 따라서 C-TEC-005·006은 **AI 기능이 추가될 경우** 적용되는 상시 제약이다.

### AI를 붙일 때의 규약

| ID | 규약 |
| --- | --- |
| `TEC-AI-001` | Vercel AI SDK로 외부 API 호출. 자체 추론 서버 금지 |
| `TEC-AI-002` | Gemini 기본. **환경 변수 변경만으로 모델 교체** 가능해야 한다 |
| `TEC-AI-003` | SDK 표준 인터페이스로만. 벤더 전용 파라미터 직접 의존 금지 |
| `TEC-AI-004` | API 키는 서버 측 환경 변수로만. 클라이언트 번들 포함 금지 |
| `TEC-AI-005` | AI 호출은 **Server Action 또는 Route Handler에서만** |

### AI를 절대 붙일 수 없는 영역 — 5곳

**규제 제약이 직접 충돌한다. 예외 없다.**

| 영역 | 금지 근거 |
| --- | --- |
| 세액·한도 계산 | 법정 산식. **확률적 생성으로 원 단위 일치를 충족할 수 없다** |
| 완료일 예측 | 밴드 산출 규격이 확정됨. 추정 방식 변경은 PRD 변경 사항 |
| 세무 관련 안내문 생성 | **세무사법 §2 4호** — 조세 상담·자문 저촉 |
| 종목 관련 문구 생성 | **자본시장법 §6⑦** — 종목·수량·시기 지정 저촉 |
| 거절 사유 평이화 | PRD가 **매핑표 방식**을 확정. 생성형 변환은 금소법 §21① 단정 금지 위반 위험 |

> **거절 사유 평이화는 AI를 붙이고 싶어지는 자리다.** 그러나 같은 사유 코드에 매번 다른 문구가 나오면 고객이 다른 안내를 받게 되고, 생성 문구가 "압류 대상자" 같은 **사람 규정 표현**을 만들 위험이 있다.

## 이미 알려진 충돌 7건 — 다시 발견하지 않는다

SRS §9에 기록되어 있다. 아래는 **이미 논의된 것**이므로 새로 제기하지 않는다.

| ID | 충돌 | 완화 | 상태 |
| --- | --- | :---: | --- |
| CONFLICT-01 | 콜드 스타트 vs p95 500ms | 부분 | Edge Runtime + TTL 캐시 + 워밍. **실측 미완** (FR-050) |
| CONFLICT-02 | 실행 한도 vs 상시 배치 | 부분 | Cron 재정의. **60초 알림은 원장 push 필요** |
| CONFLICT-03 | 재계산 300ms | ✅ | 도메인 모듈 클라이언트 동시 실행 |
| CONFLICT-04 | 커넥션 한도 | ✅ | 풀러 경유 + 전역 싱글턴 |
| CONFLICT-05 | Cron 중복 실행 | ✅ | 멱등 갱신 |
| CONFLICT-06 | 전문 수신 경로 | 조건부 | **중계 시스템 미확인** (OPEN-TEC-004) |
| CONFLICT-07 | 퍼블릭 클라우드 vs 금융권 요건 | — | **규제 검토 필요** (OPEN-TEC-005) |

**새 충돌을 찾으면** SRS §9에 같은 형식으로 추가한다 — 충돌 / 영향 요구사항 / 완화 / 잔여 위험 / Open.

---

## 위반을 발견했을 때

1. **멈춘다.** 우회 코드를 쓰지 않는다
2. 어느 제약(C-TEC / TEC-*)에 걸리는지 ID로 특정한다
3. 대안이 §9 충돌 대장에 이미 있는지 확인한다
4. 없으면 **새 충돌로 기록**하고 사람에게 판단을 요청한다

**"기술적으로 이게 맞습니다"는 우회의 근거가 되지 못한다.** 제약을 바꾸는 것은 발주 측 결정이다.
